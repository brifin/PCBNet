# 赛题六 PCB 原理图自动解析 —— 评测标准（逐字段判定细则）

> 依据：《"长沙银行杯"2026 创芯大赛·赛题六技术方案分析报告》、公开数据集命名规律（Naming_Analysis.md）、以及本仓库 `pcbnet/scorer.py` 的实际实现逐条对齐。
>
> **2026-10-14 版（相对上一版的四点变化）**：
> ① 空间阈值 **统一 20 px**（元件 bbox、IC 引脚端点、导线线段端点共用）；
> ② 普通元件（非 box）的 pin **不再计位置分**，也**不再按 pin 计连接关系分**（PinF1 只统计 box IC 引脚）；
> ③ 连接关系改为**两级**：box IC 按 **pin 节点**（`U1.7`）对齐，普通元件按 **元件节点**（`C6`，多引脚折叠为一个节点）对齐；
> ④ **GND/电源符号**（type `gnd`/`v`）不再按自动编号的 key 对齐，改按 **类别 + value + 几何位置** 匹配。

---

## 0. 总分公式与权重

```
Score_Accuracy_SingleCase = 100 × (0.3·ComponentF1
                                 + 0.25·PinF1
                                 + 0.35·NetHypergraphF1
                                 + 0.1·NetLineF1)
```

| 分项 | 权重 | 考察对象 | 关键阈值 |
|---|---:|---|---|
| ComponentF1 | 0.30 | 元件 key + type + bbox + 必要文本 | bbox 20 px |
| PinF1 | 0.25 | **box IC** 的 pin number + pin name + 端点坐标 | 20 px |
| NetHypergraphF1 | 0.35 | 哪些**节点**电气相连（IC 为 pin 节点，普通元件为元件节点） | 匈牙利匹配 |
| NetLineF1 | 0.10 | net 内导线线段（每条恰好 2 点） | 20 px |

**空间阈值统一（①）**：元件 bbox、IC 引脚端点、导线端点三者共用 **20 px**（`configs/default.yaml` 的 `thresholds.bbox_px / pin_px / line_px`）。

每项 F1 按 `F1 = 2·P·R/(P+R)` 计算，`P = TP/(TP+FP)`，`R = TP/(TP+FN)`；当 TP=FP=FN=0 时该项计 1.0（空集视为完全一致）。

**级联（最重要）**：Component key 一旦对不上，挂在该元件下的全部 pin 和 net 一并丢分。`U3` 写成 `U8`，该元件、其所有 pin、相关 net 全部算错。

## 1. 全局坐标与字符串约定

- **坐标系**：左下角原点，x 向右增大，y 向上增大。`bbox = [x1, y1, x2, y2]`，`(x1,y1)` 为左下角、`(x2,y2)` 为右上角。
- **图像坐标转换**：写出 JSON 前统一做 `y' = H − y`（H 为图像高度）。
- **字符串匹配**：严格逐字符匹配，**大小写与空格敏感**。`10k`、`10K`、`10 k` 视为三个不同值。
- **JSON 三个顶层字段**：`components`、`pins`、`nets`，缺一不可（schema 非法则整案 0 分兜底，失败也应输出空结构）。

## 2. Components（ComponentF1，权重 30%）

### 2.1 一个元件的判定流程

对一个 GT 元件，判定它是否"命中"需同时满足：

1. **key 命中**：`pred.components` 中存在同名 key（`∅<编号>` 与 GND/电源符号例外，见 2.3 / 2.4）。
2. **type 相等**：`pred.type == gt.type`（race 词表，严格相等）。
3. **bbox 匹配**：中心点欧氏距离 ≤ 20 px，**或** 四角坐标差均 ≤ 20 px（满足其一即可）。

### 2.2 逐词条判定

| 词条 | 是否参与比较 | 判定规则 |
|---|---|---|
| **key**（字典键） | ✅ 参与（∅ 例外） | 与 GT 的 key 完全相等；重名元件按出现顺序编 `_1/_2/…` 保证唯一 |
| **`type`** | ✅ 参与 | 严格等于 GT 的 type（race 词表，约 40 种：`r/c/l/d/led/box/gnd/v/net_input/...`） |
| **`bbox`** | ✅ 参与 | `[x1,y1,x2,y2]`；中心距离 ≤ 20 px 或四角差 ≤ 20 px |
| **`Name`** | ✅ 参与（∅ 例外） | 严格字符串匹配 |
| **`value`** | ✅ 参与 | 严格字符串匹配（GND/电源符号：value 参与匹配，见 2.4） |

key为以∅开头的元件，只需要比较type、bbox和value（是否存在）

### 2.3 `∅<编号>` 元件的特殊规则（本题明确要求）

当 **GT 的 key 是 `∅<编号>`**（无位号元件：网络标签端口、杂项符号等；**不含** GND/电源符号）时：

- **key 不做对比**：`∅` 后的编号是任意编号，pred 的 `∅` 编号与 GT 不同也允许，改按 **type + bbox** 与 GT 的 `∅` 元件对齐；
- **`Name` 不做对比**：无真实位号/名称，`Name` 字段不参与比较；
- **`value` 只比"是否存在"**。

有真实位号的元件（`R5/U1/C6/…`）仍按 **key 严格匹配**，不受此规则影响。

### 2.4 GND/电源符号（④ 新规则）

`type` 为 `gnd`（接地符号）或 `v`（电源符号）的元件，**不再按自动编号的 key 对齐**，改按三维度匹配：

1. **类别**：`type` 必须相同（`gnd` 只与 `gnd` 配、`v` 只与 `v` 配）；
2. **值**：`value` 必须严格相等（`GND`、`+3.3V`、`VCC`…；GT/pred 都为空视为相等）；
3. **几何位置**：在上述两条都满足的候选里，按 bbox 中心距最近者配对（匈牙利匹配，阈值 20 px）。

判定：配对成功的 GND/电源符号 → **TP**（type+bbox+value 均已保证一致）；因类别、值或位置对不上的 → 该 GT 元件 **FN**，同时 pred 中对应的符号计 **FP**。

### 2.5 TP/FP/FN 统计

- GT 元件在 pred 中存在同名 key 且通过 2.1（或 2.3/2.4 的对齐规则） → **TP**；
- GT 元件在 pred 中 key 不匹配或判定失败 → **FN**（同时产生 1 个 FP，因 pred 多占了一个错误 key）；
- pred 中多余的、GT 没有的 key → **FP**。

## 3. Pins（PinF1，权重 25%）

### 3.1 判定流程（级联）

1. **先匹配 component key**（与 Component 一致；`∅` / GND/电源符号按 2.3、2.4 对齐后的 key）。
2. **② 普通元件（非 box）的 pin 不再计位置分**——PinF1 **只统计 box IC 引脚**；普通元件的 `pins` 仍要输出（影响连接关系分），但其中的 pin 坐标不参与 PinF1 的 TP/FP/FN。
3. **再匹配 pin key与pinname**：只有 box 类 IC 元件才进行 pin key 和 pinname 的匹配。box 类元件 pin key 格式 `pin_<number>`，number 为引脚附近的编号数字，pinname 是引脚附近的文字，在 `BoxICLibrary_200cases.json` 中 number 与 pinname 有一一对应关系。
4. **端点坐标**：`point` 与 GT 端点欧氏距离 ≤ **20 px**（① 统一阈值）。

### 3.2 逐词条判定

| 词条 | 判定规则 |
|---|---|
| **pin 第二层 key** | **只有 box 类元件**需要对比，形如 `pin_<number>` |
| **`pinname`** | **只有 box 类元件**需要对比，严格字符串匹配 |
| **`point`** | `{"x","y"}` 端点坐标，与 GT 距离 ≤ **20 px** |

> pin number 与 pin name 只有在 box 类 IC 上才在图上可见；普通元件的 pin 只用于 ③ 连接关系（且按元件整体对齐，不看具体 pin）。

### 3.3 TP/FP/FN 统计

- **box IC** 下、pin number 对应且 pinname+坐标都对 → **TP**；
- box IC 引脚缺失或判定失败 → **FN**；pred 多出的 box 引脚 → **FP**；
- 普通元件的引脚：**不计入 PinF1**（当整个测例没有任何 box IC 引脚时，该项按 §0 的空集规则计 1.0）。

## 4. Nets.hyperGraph（NetHypergraphF1，权重 35%）

### 4.1 判定流程（③ 两级连接关系）

1. 每个 net 的 `hyperGraph` 解析为 **节点集合**，节点按元件类别两级归一：
   - **box IC → pin 节点**：`<component_key>.<pin_number>`，例如 `U1.114`；
   - **普通元件（含 GND/电源符号、网络端口等）→ 元件节点**：`<component_key>`，例如 `C6`、`∅589`。该元件无论有几个引脚接进该网，都**只算 1 个节点**。
2. 在 GT 的 net 与 pred 的 net 之间用 **匈牙利算法** 做最优匹配，匹配代价 = `1 − Jaccard(节点集合)`（交集/并集）。
3. 匹配上的 net 对，逐节点比 TP/FP/FN。

> 变化点：普通元件不再按 pin 拆开比较——`C6` 的 1、2 脚接进同一个网时，GT 与 pred 都只贡献 1 个节点，任一引脚接错不再单独扣分；IC 仍逐 pin 对齐，接错哪个引脚即丢哪个节点。

### 4.2 逐词条判定

| 词条 | 判定规则 |
|---|---|
| **net key**（字典键） | **不要求与 GT 一致**；只需节点集合正确。统一采用 `net_<序号>`，顺序不重要 |
| **`hyperGraph`** | 格式 `(<节点>, ...)`；节点集合必须与 GT 一致（Jaccard 最优匹配） |

### 4.3 飞线 / 电源地规则（影响 pin set 正确性）

- **飞线（同名网络标签）**：多个同名、物理分散的**非 VCC/GND** 标签逻辑并网为一个 hyperGraph；漏掉任一侧 pin，hyperGraph 即错。
- **VCC/GND**：视为普通电源网络，**不当飞线**，但相关符号要并到电源网（GND/电源符号本身按 2.4 对齐、并按元件节点参与连接关系）。
- **红 pin 直连**（无绿线、端点重合）：两 pin 端点重合即电气相连，同网。

---

## 5. Nets.edges（NetLineF1，权重 10%）

### 5.1 判定流程

1. 每条 edge **必须恰好 2 个点**（折线必须拆成多条两点线段，不得写成 `[p1,p2,p3]`）。
2. 线段的两个端点与 GT 对应线段端点距离 ≤ **20 px**（① 统一阈值；线段可反向匹配）。
3. 线段必须挂在**正确 matched net** 的 `edges` 下——位置接近但网错了**不得分**。

### 5.2 逐词条判定

| 词条 | 判定规则 |
|---|---|
| **`edges` 的每条 `edge_序号`** | 形如 `[{x1,y1},{x2,y2}]`，恰好 2 点，edge的序号无所谓；与 GT 线段端点匹配（`min(端点顺配, 端点反配) ≤ 2×20 px`） |
| **飞线 net 的 edge** | 通常为零长度线段（起点 = 终点） |

## 6. 评测陷阱清单（写 JSON 后必查）

- [ ] 每个 pin 属于某个 component。
- [ ] 每条 edge 恰好 2 个点。
- [ ] 重名 key 已加 `_1/_2/…` 后缀。
- [ ] 坐标已从图像左上角翻转为左下角（`y' = H − y`）。
- [ ] 字符串严格匹配（大小写、空格不归一化）。
- [ ] GND/电源符号的 `value` 尽量读出（`GND`/`+3.3V`…），否则 ④ 的匹配会直接失败。
- [ ] 普通元件的引脚也要输出（连接关系按元件节点计），但不必纠结其坐标精度。
