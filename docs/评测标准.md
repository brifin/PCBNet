# 赛题六 PCB 原理图自动解析 —— 评测标准（逐字段判定细则）

> 依据：《"长沙银行杯"2026 创芯大赛·赛题六技术方案分析报告》、公开数据集命名规律（Naming_Analysis.md）、以及本仓库 `pcbnet/scorer.py` 的实际实现逐条对齐。

---

## 0. 总分公式与权重

```
Score_Accuracy_SingleCase = 100 × (0.3·ComponentF1
                                 + 0.25·PinF1
                                 + 0.35·NetHypergraphF1
                                 + 0.1·NetLineF1)
```

| 分项 | 权重 | 考察对象 | 关键阈值 |
|---|---:|---|---|
| ComponentF1 | 0.30 | 元件 key + type + bbox + 必要文本 | bbox 20 px |
| PinF1 | 0.25 | pin number + pin name + 端点坐标 | 10 px |
| NetHypergraphF1 | 0.35 | 哪些 pin 电气相连（pin set） | 匈牙利匹配 |
| NetLineF1 | 0.10 | net 内导线线段（每条恰好 2 点） | 10 px |

每项 F1 按 `F1 = 2·P·R/(P+R)` 计算，`P = TP/(TP+FP)`，`R = TP/(TP+FN)`；当 TP=FP=FN=0 时该项计 1.0（空集视为完全一致）。

**级联（最重要）**：Component key 一旦对不上，挂在该元件下的全部 pin 和 net 一并丢分。`U3` 写成 `U8`，该元件、其所有 pin、相关 net 全部算错。

## 1. 全局坐标与字符串约定

- **坐标系**：左下角原点，x 向右增大，y 向上增大。`bbox = [x1, y1, x2, y2]`，`(x1,y1)` 为左下角、`(x2,y2)` 为右上角。
- **图像坐标转换**：写出 JSON 前统一做 `y' = H − y`（H 为图像高度）。
- **字符串匹配**：严格逐字符匹配，**大小写与空格敏感**。`10k`、`10K`、`10 k` 视为三个不同值。
- **JSON 三个顶层字段**：`components`、`pins`、`nets`，缺一不可（schema 非法则整案 0 分兜底，失败也应输出空结构）。

## 2. Components（ComponentF1，权重 30%）

### 2.1 一个元件的判定流程

对一个 GT 元件，判定它是否"命中"需同时满足：

1. **key 命中**：`pred.components` 中存在同名 key（`∅<编号>` 例外，见 2.3）。
2. **type 相等**：`pred.type == gt.type`（race 词表，严格相等）。
3. **bbox 匹配**：中心点欧氏距离 ≤ 20 px，**或** 四角坐标差均 ≤ 20 px（满足其一即可）。

### 2.2 逐词条判定

| 词条 | 是否参与比较 | 判定规则 |
|---|---|---|
| **key**（字典键） | ✅ 参与（∅ 例外） | 与 GT 的 key 完全相等；重名元件按出现顺序编 `_1/_2/…` 保证唯一 |
| **`type`** | ✅ 参与 | 严格等于 GT 的 type（race 词表，约 40 种：`r/c/l/d/led/box/gnd/v/net_input/...`） |
| **`bbox`** | ✅ 参与 | `[x1,y1,x2,y2]`；中心距离 ≤ 20 px 或四角差 ≤ 20 px |
| **`Name`** | ✅ 参与（∅ 例外） | 严格字符串匹配 |
| **`value`** | ✅ 参与 | 严格字符串匹配 |

key为以∅开头的元件，只需要比较type、bbox和value（是否存在）

### 2.3 `∅<编号>` 元件的特殊规则（本题明确要求）

当 **GT 的 key 是 `∅<编号>`**（无位号元件：电源/地符号、网络标签端口等）时：

- **key 不做对比**：`∅` 后的编号是任意编号，pred 的 `∅` 编号与 GT 不同也允许，改按 **type + bbox**与 GT 的 `∅` 元件对齐；
- **`Name` 不做对比**：无真实位号/名称，`Name` 字段不参与比较。

有真实位号的元件（`R5/U1/C6/…`）仍按 **key 严格匹配**，不受此规则影响。

### 2.5 TP/FP/FN 统计

- GT 元件在 pred 中存在同名 key 且通过 2.1 → **TP**；
- GT 元件在 pred 中 key 不匹配或判定失败 → **FN**（同时产生 1 个 FP，因 pred 多占了一个错误 key）；
- pred 中多余的、GT 没有的 key → **FP**。

## 3. Pins（PinF1，权重 25%）

### 3.1 判定流程（级联）

1. **先匹配 component key**（与 Component 一致；`∅` 元件按 type+bbox 对齐后的 key）。
2. **再匹配 pin key与pinname**：一般来说，只有box类ic元件才进行pin key和pinname的匹配，box类别元件pin key格式`pin_<number>`，number为引脚附近的编号数字，pinname是引脚附近的文字，在BoxICLibrary_200cases.json中number与pinname有一一对应关系；对于非box元件来说，pin key就是pin_<pinname>的形式，pinname就是1，2，...，顺序随机，所以非box元件还是看坐标是否正确。
4. **端点坐标**：`point` 与 GT 端点欧氏距离 ≤ 10 px。

### 3.2 逐词条判定

| 词条 | 判定规则 |
|---|---|
| **pin 第二层 key** | 只有box类元件需要对比，形如 `pin_<number>` |
| **`pinname`** | 只有box类元件需要对比，严格字符串匹配 |
| **`point`** | `{"x","y"}` 端点坐标，与 GT 距离 ≤ 10 px |

> pin number 与 pin name 只有在 box 类 IC 上才在图上可见

### 3.3 TP/FP/FN 统计

- 匹配的元件下、pin number 对应且 pinname+坐标都对 → **TP**；
- 缺失或判定失败 → **FN**；
- pred 多出的 pin → **FP**。

## 4. Nets.hyperGraph（NetHypergraphF1，权重 35%）

### 4.1 判定流程

1. 每个 net 的 `hyperGraph` 解析为一个 **pin 集合**，元素格式 `<component_key>.<pinname（box元件是number，非box元件是pinname）>`（例如 `U1.114`、`R1.1`、`∅589.587`）。
2. 在 GT 的 net 与 pred 的 net 之间用 **匈牙利算法** 做最优匹配，匹配代价 = `1 − Jaccard(pin 集合)`（交集/并集）。
3. 匹配上的 net 对，逐 pin 比 TP/FP/FN。

### 4.2 逐词条判定

| 词条 | 判定规则 |
|---|---|
| **net key**（字典键） | **不要求与 GT 一致**；只需 pin set 正确。统一采用 `net_<序号>`，顺序不重要 |
| **`hyperGraph`** | 格式 `(<component_key>.<pinname（box元件是number，非box元件是pinname）, ...)`；pin set 必须与 GT 一致（Jaccard 最优匹配） |

### 4.3 飞线 / 电源地规则（影响 pin set 正确性）

- **飞线（同名网络标签）**：多个同名、物理分散的**非 VCC/GND** 标签逻辑并网为一个 hyperGraph；漏掉任一侧 pin，hyperGraph 即错。
- **VCC/GND**：视为普通电源网络，**不当飞线**，但相关符号要并到电源网。
- **红 pin 直连**（无绿线、端点重合）：两 pin 端点重合即电气相连，同网。

---

## 5. Nets.edges（NetLineF1，权重 10%）

### 5.1 判定流程

1. 每条 edge **必须恰好 2 个点**（折线必须拆成多条两点线段，不得写成 `[p1,p2,p3]`）。
2. 线段的两个端点与 GT 对应线段端点距离 ≤ 10 px（线段可反向匹配）。
3. 线段必须挂在**正确 matched net** 的 `edges` 下——位置接近但网错了**不得分**。

### 5.2 逐词条判定

| 词条 | 判定规则 |
|---|---|
| **`edges` 的每条 `edge_序号`** | 形如 `[{x1,y1},{x2,y2}]`，恰好 2 点，edge的序号无所谓；与 GT 线段端点匹配（`min(端点顺配, 端点反配) ≤ 2×10 px`） |
| **飞线 net 的 edge** | 通常为零长度线段（起点 = 终点） |

## 6. 评测陷阱清单（写 JSON 后必查）

- [ ] 每个 pin 属于某个 component。
- [ ] 每条 edge 恰好 2 个点。
- [ ] 重名 key 已加 `_1/_2/…` 后缀。
- [ ] 坐标已从图像左上角翻转为左下角（`y' = H − y`）。
- [ ] 字符串严格匹配（大小写、空格不归一化）。
