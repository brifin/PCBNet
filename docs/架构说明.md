# PCB 原理图自动解析——代码框架及实现逻辑说明

## 一、这套代码要解决什么

竞赛任务：**把一张 PCB 原理图（图像）解析成结构化 JSON**，输出三类对象：`components`（元件）、`pins`（引脚）、`nets`（网络/连线）。评分是四项 F1 的加权和（`pcbnet/scorer.py`）：

| 项 | 权重 | 匹配判据 |
|---|---|---|
| ComponentF1 | 30% | key 相同 + type 相同 + bbox 中心≤20px + (IC 比 name / 阻容比 value) |
| PinF1 | 25% | pinname 相同 + 端点≤5px |
| NetHypergraphF1 | 35% | 网络超图按 Jaccard 用匈牙利匹配后逐引脚比 |
| NetLineF1 | 10% | 两点线段端点距离≤5px |

关键难点是**级联硬匹配**：元件 key 对不上，挂在它下面的 pin/net 全部归零。这也是之前 0 分的根因，整套架构都是围绕“先把元件感知和 key 做对”来设计的。

## 三、主数据流（推理时 image → JSON）

入口只有三行，把三阶段串起来：

```python
def infer_image(image_path, cfg=None, out_json=None):
    vision = extract_vision(image_path, cfg)      # 阶段1 感知
    contest = build_structure(vision, cfg)        # 阶段2 结构化
    contest = correct(contest, cfg)               # 阶段3 纠错
```

### 阶段1 `stage1_vision.py`——感知

产出一个 `VisionOut`（元件框 / 文本框 / 引脚端点 / 导线骨架 / 两点线段）：

- **检测**：YOLO 一次性检出后，`_split_detections` 按类别拆成三堆——元件、`text`、`pin_tip`，**严禁把文字/引脚当成元件**（这是过检的主因）。没有权重时退化为规则兜底。
- **OCR**：优先对检出的 `text` 框做裁剪 OCR（PaddleOCR），竖排文字会旋转 90° 再识别；没有 text 框时回退整图 OCR。
- **导线**：U-Net 分割导线 → 骨架化 → 得到线段。

### 阶段2 `stage2_structure.py`——结构化（当前主瓶颈）

把感知结果拼成电路结构：

- **文本分类**：`_classify_text` 判断每段文字是位号/值/名称/引脚号/垃圾。
- **绑字（匈牙利三约束）**：`_bind_designators` 用匈牙利算法把位号最优绑到元件（类别一致 + 几何对齐 + 局部唯一），位号走严格正则、value 不改大小写。
- **建引脚**：`_pins_for_component` 优先用检出的 `pin_tip`，否则按元件类型几何估计，再 `_snap_to_wire` 吸附到导线端点。
- **连网**：在导线骨架上做连通域把引脚并成 net（Union-Find / 连通分量），`_merge_flywires` 处理同名标签飞线；导出两点 `edges`。

### 阶段3 `stage3_correct.py`——低置信纠错（默认关）

只对“看起来错”的文本（如 O/0、l/1 混淆）先做规则修复；仍不确定且预算够，才调 `QwenClient`。默认 `stage3.enabled=false`，且离线时 `QwenClient` 自动跳过——符合内网安全约束。

## 四、真值适配 `gt_adapter.py`（很关键）

数据集是 `CVJsonStd` 格式，得先转成竞赛 JSON 才能训练和评分。它优先用 `associatedTexts` 里的 `details` 字段（`designator`/`value`）取权威位号/值，过滤掉 “Schematic1” 这类图名垃圾，并优先用 `keyPointPaths.wire` 生成干净的两点线段。**它的质量直接决定训练标签和评估上限**。

## 六、诊断工具（这套框架的一大特色）

因为直接看总分不知道瓶颈在哪，代码内置了三种诊断口径：

1. **Oracle 阶梯**（`oracle.py`）：逐层把真值注入流水线（L0 真实→L1 给真元件+文本→L2 加真引脚→L3 加真导线→L4 全真），哪一层分数跳上去，瓶颈就在那一层。之前定位到瓶颈在阶段2。
2. **ConfidentScore**（`scorer.filter_confident`）：本地 Dataset300 里很多元件没有真实位号，只能用 `C_15` 这种内部 id 当 key，图上根本认不出来，会把分数人为压低。这个口径只统计**有真实位号**（如 U3/R1/RUN_1）的元件，给出更诚实的能力上限。
3. **AlignedScore**（`scorer.align_prediction`）：把预测 key 按 type+bbox 最优重映射到真值 key 后再打分，用来区分“是感知错了”还是“只是 key/位号没对上”。冒烟输出里的 `aligned_score` `mapped=` 就是它。

## 七、配置 `configs/default.yaml`

集中管理阈值（bbox 20 / pin 5 / line 5 px）、四项权重、模型权重路径、训练超参、OCR 置信门限 `conf_tau`、引脚吸附距离、stage3 开关与预算。**注意 `yolo_weights`/`unet_weights` 目前是空**——旧的 28 类权重已废弃，必须按新的 16 类重训后再填回来。

## 八、当前状态 & 短板

- 打分器/适配器自检满分（`self_score=100`），链路是通的。
- 但 `yolo_weights` 为空 → 现在走规则弱感知 → 严重过检 → 实测 ≈0 分。
- **提分第一优先级是训练检测器**，其次是阶段2 的绑字与连网。
